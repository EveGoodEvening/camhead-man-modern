## 0. 约定与裁定

### 0.1 语言与标识符
- 所有面向玩家的文字都用简体中文，集中放在 `src/data/zh.ts`，其他模块只引用 key。
- 代码引用的一切都用英文标识符：地点、点位、NPC、物品、flag、谜题、拍摄目标、微信消息、剧情节拍。本文出现的 `code` 字样就是最终 id，**不许改名**。确需新增时，只能追加，不能改动已有的。
- 表格里的「我」指主角。他不出声，他的话以打字的形式同时出现在背屏和对话框里。名牌在 `name_known` 之前显示「？？？」，之后显示「周远」。

### 0.2 坐标约定（全局唯一）
- `PLANET_R = 80` m，`PLANET_CENTER = (0,0,0)`（TECH 的约定），城镇位于 **+Y 极**。
- **整座城只有一张北极图（chart）**：n = +Y，e1 = +X，e2 = +Z，也就是 ART §6.2 的通用 `chartToWorld`，参数取北极图。极点就是山顶的大榕树。
- 地点用**图极坐标 `(r, lon, h)`** 给出：
  - `r` 是从极点沿球面量的弧长（米）。
  - `lon` 是经度（度），从 +Z 起算，向 +X 递增，与 TECH 的 `dirFromLatLon` 一致。
  - `h` 是离地高度（米）。
  - 换算：`x = r·sin(lon)`，`z = r·cos(lon)`，`lat = 90° − r·0.716197°`。
- **方位**：局部「北」= 朝极点（上山、朝榕树），「南」= 朝外（朝海），「东」= lon 增大的方向，「西」= lon 减小的方向。
- `yaw`/heading 是从局部北起算的**顺时针角度**（从星球外俯视），与 TECH 的 `teleport(lat, lon, headingDeg)` 一致。所以：yaw 0 = 面朝山顶，90 = 沿环路向东（lon 增大），180 = 面朝海。
- 城镇地面是一张半径 64 m（0.8 rad）的细分圆盘，超出部分是海（ART §6.3）。码头和灯塔伸到 r ≈ 71 m。刚性摆放的物体在 0.8 rad 外也没问题；码头这类沿径向贴合的长条几何，末端切向会压缩约 10%，可以接受。
- 允许微调：世界代理可以在 **±2 m / ±3°** 内移动任何点位，改完同步更新 `src/data/locations.ts`。谜题的机位（`vp_*`、`pk_*`）和遮挡关系（P8）用 §9 给的**构造规则**算出来，不硬编码。
- **物件点位与站立点：** §5.4 里 yaw 写「—」的点位，以及标明是物件本身位置的点位（`sp_donation_box`、`sp_temple_idol`、`sp_manhole`、`sp_market_tank`、`sp_chai`、`sp_net_dot`、`sp_mirror`、`st_*`/`dk_*` 家具），都是**物件位置**。`goto()` 到这类点位时，玩家站在世界代理给出的站立点 `stand`（物件前方开阔一侧 1.8 m，面朝物件）上，而不是站进物件里。NPC 占用的点位按 ARCH §2.8.4 的「演员规则」处理。

## 1. 标题与 Pitch

- **中文名：** 《显影》
- **副标题：** 望潮里志怪
- **英文：** *XIANYING — Strange Tales of Wangchao Lane*
- **标题画面：** 青绿平底色 `#65c1bc` 上，一颗小星球缓缓自转，顶上是一座海边老城。「显影」两个字用 ZCOOL QingKe HuangYou，白字、墨线描边、带挤出阴影；下面一行小字「望潮里志怪」。黄色按钮写 **「开机」**，既是手机开机，也是剧组开机。有存档时，在下面加两个白色小按钮「继续」和「设置」；通关后存档是结局检查点，「继续」写作「重温结局」（§10.2 #49）。标题字体可以用 Google Fonts 的 `&text=显影望潮里志怪开机继续设置` 子集链接预先加载，避免切片延迟。仍需 `document.fonts.load`（TECH §5）。

**一句话：** 拆迁前夜，一个脑袋是手机摄像头的男人，用镜头找回自己的脸。

**Pitch：**
望潮里是一颗小星球。山顶一棵大榕树，环山一条老街，外头就是海，绕一圈走不到七十秒。明早六点整，这里要拆。

清晨，一个男人在公交站醒来，脑袋是一台手机，脸是它的摄像头。背屏亮着一行字：面容 ID 无法识别。与此同时，街坊们发现老照片上的人脸正在一张张变糊；工地围挡上那个红圈“拆”字，一到晚上就醒了。

他没有嘴，只有快门。他用长焦去读远处的门牌，用夜景去看见土地公和纸人，用闪光把一个没有主人的影子单独照出来，还会把头摘下来塞进鸽子笼里看。他要找回被“拆”撕成四格的一卷胶卷，在父亲的暗房里冲洗出来，最后自己站进照片里。

这里没有战斗，没有死亡，也没有失败惩罚。玩一遍 25–35 分钟。

**主题：** 拍照的人，不在照片里。

**五句话结构：**
1. 醒来，没有脸。
2. 发现一卷为他留了位置的胶卷。
3. 镜子里认出自己是“手机 97%，人 3%”。
4. 拍掉“拆”的一点，让它变成“折”，全城的人脸都回来了。
5. 天亮时，他摘下头放上三脚架，让没有头的身体走进合影。

## 2. 主角：周远（机头人）

### 2.1 外观（在 ART §7.2 基础上补充；尺寸、颜色以 ART 为准）
- 男性，身高 1.86 m（量到手机顶）。炭灰色工装夹克 `#333d40`，领口、袖口和拉链条是橙色 `#d8944c`；藏青裤；白色大号球鞋，鞋底有橙色条纹；斜挎一只鼠尾草绿的小包。
- **头是一台竖放的手机**（`RoundedBox 0.24 × 0.40 × 0.075`，后仰 4°），侧边框是橙色的，从背后看是一圈橙色轮廓。
- **朝前的一面，也就是手机背面，是他的脸**：
  - 炭灰色镜头模组，里面两颗主镜头当眼睛，光圈叶片的开合就是表情。
  - 下方一颗小镜头当嘴，说话时会张开。
  - 右下角一颗黄色闪光灯。
  - **新增：** 模组下方贴着一张直径 0.05 m 的圆形旧贴纸。白底，蓝字 `#2a8595`，写着「周记照相馆」，边缘磨损，用 canvas 绘制。第三人称下看不见，只在对话特写和凸面镜里看得到，是 `S_mirror` 的名字线索。
- **朝后的一面是屏幕，对着越肩相机**，是戏内 HUD（128×256 CanvasTexture，状态变化时才重绘）：
  - 顶部状态栏从左到右：**信号格**（0–4 格，是谜题线索，见 §3.10）、时间（Silkscreen 字体）、**电量 1%**（整局都是 1%，从不关机）。
  - 中间是线稿表情：`平静 (· ·)`、`开心 (^ ^)`、`疑惑 (? ·)`、`惊讶 (O O)`、`害怕 (> <)`、`思考 (…)`、`发现 (!)`（4 m 内有可交互线索时以 2 Hz 闪烁）。
  - 其他状态：`● REC`（取景中）、`信号干扰`（10 m 内有怪时显示静电雪花）、`打字中`（他说话时逐字出现）、`乘车码`（P7）、`出示`（展示照片时，两张照片会以 2 Hz 交替）。
  - **志怪签名：** 在 `S_wake` 结尾和 `S_mirror` 时，屏幕会用 0.5 s 显示一张**不是他的人脸**：线稿，平静得过分的笑。
- **脖子**是皮肤色圆柱，插进手机底部的 USB-C 口。**摘头**时露出一个金属色的小插头，效果滑稽，不血腥。
- 他的身体在任何状态下都不直接显示人脸。只有 `PHOTO_ONLY` 图层（只在终章合影照片里渲染）会把手机头替换成一颗有脸的人头：眉眼像老周，短发 `#3c4e54`。

### 2.2 性格与说话方式
- 温吞，嘴笨，观察力极强，吐槽很冷。他打字，不说话，句子短，常常只打一个省略号。
- 惯用句式：「……」「嗯。」「面容 ID 无法识别。」「电量 1%。好像一直是 1%。」
- 人物弧光：从隔着屏幕看世界的人，变成站进照片里的人。

### 2.3 身世（剧透，按揭示顺序）
1. **序章**：他叫不出自己的名字。相册里只有一张 2006 年的全街合影，照片上所有人的脸都糊了。
2. **第一章**：他拿到快递柜里寄存了 1096 天的钥匙和字条，看到照相馆门框上的铅笔身高线「远 七岁 / 远 十二岁 / 远 十八岁」，听到老人机里的语音「阿远……」。
3. **第二章（中点）**：他在凸面镜里自拍，识别结果是 **「手机 97% · 人 3%」**，还读出了贴纸上的「周记照相馆」。土地告诉他：那 3% 是你还记得的东西。
4. **第三章**：他在零号线实名认证时，必须输入自己的名字：**周远**。之后名牌变成「周远」，所有人的台词随之改变。
5. **真相**（暗房和结局时讲全）：
   - 周远是周记照相馆老板老周的儿子。2006 年 8 月 15 日，18 岁的他在天桥下给全街拍了合影，然后去外地读书，再也没回来。那张照片里有爸爸，没有他。
   - 2023 年，老周听说片区要拆，把街坊们重新叫到天桥下，按 2006 年的构图拍了一卷**四格接片**，在正中间给儿子留了一个粉笔叉。他没冲，想等儿子回来一起冲。
   - 老周把店门钥匙寄存在便利店的快递柜里，取件码发到了儿子手机上。三个月后，老周去世。那条短信，周远一直没点开。
   - 2026 年 9 月，拆迁前夕，38 岁的周远终于坐上了回望潮里的末班车，在车上睡着了，手机电量 1%。他的魂先到了：9 月 29 日清早，在望潮里的候车亭里醒来。真相在结局的车门前由站务员说破（`att.bus`），`wx_dawn` 只预告「六点有趟车」。一个隔着手机看了半辈子世界的人，回来的时候，就只剩一台手机当脸。

## 3. 核心循环与镜头系统

### 3.1 核心循环
走动、观察 → 举起镜头（取景）→ 在对的焦段、模式、机位按快门 → 照片自动打上识别标签，存进相册（相册兼作物品栏和证据库）→ 把照片**出示**给人、灵或机器 → 打开新地点、新能力、新时段。

### 3.2 三条镜头规矩（序章 P1 之后，土地用微信发给玩家，并常驻在备忘录里）
- **① 肉眼看不见的，夜景里看得见。** 灵体图层 `GHOST` 只在夜景取景时渲染。
- **② 拍到的，就是真的。** 照片被世界承认：重拍让过去显形，少一点的“拆”就成了“折”，合影里的脸就是真的脸。
- **③ 闪光照活物，魂要等。** 活物和实物用闪光照亮；灵体必须用夜景、静止 2 s 才拍得下来。

**所有谜题都只靠这三条规矩，加上画面里给出的线索就能解开。**

### 3.4 统一判定函数 `evalShot(camera, targets)`（唯一判定入口）
下面四样东西**全部调用同一个函数**：
1. 取景框颜色，每帧计算；
2. 识别条的标签和置信度，每帧计算；
3. 快门结果；
4. 测试钩子 `__game.evalShot()`。

**候选目标：** 从当前可用的目标中选出（满足 `phases`、`requires` 且不含 `excludes` 标记的 `PhotoTarget`），要求锚点投影在 NDC 的 |x|,|y| ≤ 0.92 内，并且在镜头前方。

**多个候选时的优先级：**
1. 属于「当前激活谜题」的目标优先；
2. 其次，离画面中心近的优先；
3. 再其次，按 id 字典序。

**条件检查顺序（固定）：** 遇到第一个不满足的条件就停下，识别条只显示这一条失败提示。

`layer` → `zoom` → `occluded` → `dist` → `size` → `center` → `whole` → `facing` → `dark` → `flash` → `viewpoint` → `overlay` → `hidden` → `contain` → `still`

（P3r3 look L5：`occluded` 从 `dark` 之后提到 `zoom` 之后。原来被柱子、摊位完全挡住的王阿婆仍然提示「要正脸」，玩家以为要绕到她正面，其实是看不见她。人物目标 8 m 以内的遮挡射线还会对画面里真实渲染的物件（摊位的板子、纸箱）做一次检测，不只对粗略的遮挡体。）

| 条件 | 判定 | 默认失败提示（目标可以覆盖） |
|---|---|---|
| `layer` | 目标在 `GHOST` 图层（或标了 `needsNight`），但夜景没开 | 这里好像有东西……（夜景 N）（还没有夜景时：这里好像有东西……肉眼看不见。） |
| `zoom` | 当前焦段不在允许的集合里 | 试试 3× / 试试 10× / 退回 1× |
| `dist` | 超出 `minDist..maxDist` | 太远了 / 太近了 |
| `size` | 投影半径 ÷ 半屏高 < `minFrac` | 再近一点，或者放大 |
| `center` | 锚点不在画面中央 `frameArea` 比例的范围内 | 放到画面中间 |
| `whole` | `whole[]` 里的点没有全部落在画面 NDC 0.9 以内 | 没拍全 |
| `facing` | 对象的朝向与镜头的夹角大于 `maxAngle` | 要正脸 |
| `dark` | `needsLight` 为真，却没开闪光或头灯 | 太暗了，对不上焦 |
| `occluded` | 从镜头向锚点和 4 个包围点做射线，被遮住的超过 2 条 | 被挡住了 |
| `flash` | 要求开闪光却没开，或禁止闪光却开了 | 试试闪光（Q） / 别开闪光 |
| `viewpoint` | 离指定机位太远，或镜头方向偏差超出容差 | 按先后只报一项（P3r3）：离机位太远 → 换个位置（目标自己的「换个位置——…」）；位置对、朝向偏 → 「位置对了——往左转一点 / 往右转一点」；位置和朝向都对、仰角偏 → 「位置对了——镜头再低一点 / 镜头再抬高一点」 |
| `overlay` | 重拍类目标没有叠上对照 | 先按 R 叠上对照 |
| `hidden` | `mustBeHidden[]` 里有点没被遮住 | 那一点还露着 |
| `contain` | `mustContain[]` 里任一目标的锚点不在 NDC \|x\|,\|y\| ≤ `frameArea` 内，或被遮挡 | 还缺：{名称} |
| `still` | 夜景曝光的 2 s 内，移动输入或镜头累计转角超过 1.5° | 糊了，别动。 |

- **取景框三态：** 白色 = 画面里没有候选目标；黄色 = 有候选目标，但至少一个条件不满足，旁边显示那一条失败提示；绿色 = 全部满足，此刻按快门就能拿到标签。
- **置信度（确定性）：**
  - 全部满足时：`okConfidence ?? 90 + floor(9·q)`，其中 `q = 1 − max(|x|,|y|)/0.92`。
  - 否则：`30 + floor(50·已满足条件数 / 适用条件数)`。
- **照片标签：**
  - 判定为绿的目标，把它的 `onShot.tags` 写进照片；
  - 另外，画面中所有 NPC 和地标，只要投影占比 ≥ 0.05 且没有被遮挡，自动加上 `npc:<id>` 或 `lm:<id>` 标签（用于出示反应）。

### 3.5 实时识别条（AI 识别）
- 位置在取景 UI 底部居中，样式是白底墨框的石板条。格式：`识别：{标签} {置信度}%`，每帧更新。
- 标签按焦段分级：每个目标或景物都有 `labels: [{zoom:1,text}, {zoom:3,text}, {zoom:10,text}]`，显示「≤ 当前焦段」的那一级里最高的一条。
  - 例：1× 显示「猫」，3× 显示「黑猫 · 左耳缺角」。
- 没有候选目标时，对画面中心做射线，读命中物体的 `userData.labelId`，从景物标签表（§8.3）里取。什么都没命中就显示天空，天空标签随时段变化：白天「天空 · 青色 99%」、黄昏「天空 · 橘红 99%」、夜里「天空 · 夜 99%」、黎明「天空 · 发白 99%」（P3r3 look L5：原来粉色的黄昏天空也读「青色」）。
- 识别条是主要的戏内反馈，也负责讲笑话。

### 3.6 夜景 = 长曝光（合并实现）
- 按 N 开关夜景。开启时实时渲染 `GHOST` 图层，画面加上冷色暗角。
- 按快门后，画面上出现环形倒计时「曝光中 2…1…」。这段时间里如果有移动输入，或者镜头累计转角超过 1.5°，就中止并提示「糊了，别动。」坐在长凳上时视为完全静止。
- 成像时：
  - 标记为 `transient` 的路人被隐藏（长曝光把走动的人“等”没了）；
  - `GHOST` 图层入画；
  - 需要光轨的目标（P6）把预先画好的 canvas 光轨贴图合成进照片。
- **不做**逐帧累积（ping-pong）拖影。

### 3.7 闪光
- 按 Q 切换，取景 UI 右上角显示闪电图标。
- 带闪光拍照时：离镜头 10 m 内的表面一律按受光带渲染（照片渲染时把 `uFlashPos`/`uFlashR` 传进材质，关掉那块区域的阴影遮罩），所以**真实投影会消失**。影子贴花（`ghostShadow`）不受影响。
- 快门瞬间屏幕全白 80 ms，然后 250 ms 淡出。
- 对着镜子或玻璃开闪光会得到一张“白片”，标签「反光 · 一片白」，这张照片作废。

### 3.8 对照重拍 `rephoto`
- 参考照片**不是图片素材**：游戏载入时，从目标机位用 `PAST` 图层渲染一次，再加褐色调、颗粒和白边，所以一定能对齐。
- 重合度 `score = clamp(round(100 − 10·r), 0, 100)`，`r = max(ePos/tolPos, eYaw/tolYaw, ePitch/tolPitch)`；有一项超出容差（r > 1）时，另外两项再各加 `0.3·min(1, 比值)`，所以只有仰角不对时，走动、转身也会让数字变（P3r3：原来一直停在 82%）。焦段不对时 score 最高只到 60。四项都在容差内时，score ≥ 90。
- 取景 UI 右上角显示「重合度 87%」。≥ 90 时框变绿，按快门就“显影”：叠加层在 0.6 s 内由褐色转为彩色，然后消失。

### 3.9 出示 `show`
- 触发方式：对话选项「出示照片…」，或者在可出示对象附近按 G。弹出相册选择器，只列出本局拍的照片和获得的预设照片。
- 选择数量：默认选 1 张；只有 `receiver.acceptsPair = true` 的对象（小区门禁）允许选 2 张。
- 展示：主角转身，背屏显示选中的照片（2 张时以 2 Hz 交替）。
- 反应查表（§12）：先找 `(接收方, 照片标签)` 的专门台词；找不到就用该接收方的通用台词。

### 3.10 信号格 `signalAt(pos)`
- 4 格（满格）：天桥桥面中央 3 m 以内，且 `h ≥ 5`。
- 3 格：天桥其余部分和楼梯；老小区天台；灯塔门口。
- 2 格：环城路路面、海堤步道、码头。
- 1 格：其他室外区域。
- 0 格：猫耳巷里（「猫耳巷没信号」）、所有口袋室内。

HUD 右上角和背屏状态栏同步显示信号格。

### 3.11 摘头 `detach`
- 只能在指定的窥视点使用：`pk_coop`（鸽子笼）、`pk_psd`（屏蔽门缝），以及终章的三脚架 `tripod`。
- 流程：按 E → 0.4 s 过场（主角把头拔下，塞进缝里，USB-C 插头露出来）→ 视角切到头上，自动进入取景（可以变焦、开闪光、拍照）→ 按 E 或 Esc 装回头。
- 鸽子笼：头塞进小门里约 0.4 m、比门槛高约 0.4 m，往下看着底片上的四只鸽子（P3r3：原来贴着笼底，画面三分之二是地板）。
- 在三脚架上时，WASD 操控的是**没有头的身体**，视角停留在三脚架上（§9 `S_group_photo`）。

### 3.12 戏内导航：土地的烟
- 举起镜头 0.25 s 后，画面里出现一缕香烟（FX pass 里的带状粒子）。白天、黄昏、黎明是**墨色烟芯 + 纸白描边**，夜里是**淡金色的微光**，任何调色下都醒目；烟在屏幕上至少约 10 px 宽，永远不会缩成一个点。
- 烟从画面右下角、镜头旁 1.1 m 处升起，先往上拐，再沿**能走的路**（环路、海堤步道、天桥两侧楼梯、猫耳巷、红旗新村院子、上山小门、码头……）在街面上方约 2.4 m 飘到当前目标的点位（§10.6），最后落在目标上方；室内离地 1.5 m。路线来自一张手工路网，每段都用实时碰撞检测验证，所以关着的门、B1/B2 路障会让烟绕开，而不会穿墙、穿栏杆。每次出现时，烟从镜头往外「展开」约 0.7 s，烟身上有朝目标方向漂动的「〉」形墨纹。
- 夜里有多个目标时，烟指向最近的一个未完成目标（换目标要近出 8 m 以上，避免在两个相邻目标之间来回跳）。
- 烟的终点是玩家要站的地方：交互物够得着、面对它的位置（出照相馆 `st_exit`、出地铁 `sw_exit`）；目标点上站着角色时，是 `goto()` 会站的位置（她身前 / 身后 `approachDist`，例如海堤上纸妹身后 3 m），不是角色身上（P3r3）。
- 离终点（沿路线）不到 3.5 m，或按 R 叠上对照时，烟收起，不再横在画面里；烟身在镜头前 2.2 m 内淡入，墨芯边缘柔化、描边向外变淡（P3r3）。
- 路线里「从空地到路网」「从路网到目标」和直达的那几段，按玩家本身 0.35 m 的半径、走直线来验证；路网本身的段落若要侧身绕开电线杆、路灯，烟也画出那段绕行。山坡上（挡土墙 r 13 以内）有一圈路网节点，从小区后面、猫耳巷后面的山坡上也会被引向上山小门（lon 145°）出去（P3r3）。
- 不举镜头时，画面边缘有一个**香炉徽章 + 墨色箭头**（1280×720 下直径 44 px），指向同一条路线前方约 7 m 处，徽章朝画面内侧挂一个小牌「烟 · 23m」（沿路线剩下的米数）。它只贴着画面四边走（下边距 58 px，不会落到主角脚边、像地上的东西）。那一段路在画面中间时它不消失，而是变淡（不透明度 0.5）留在它指的那条边上（通常是上边），告诉玩家「方向对，接着走」；离目标不到 3.5 m 时淡出。第一次出现时，旁边冒一个气泡「这炷香跟着土地的烟——箭头指着下一步」，在屏幕上累计 7 s 后消失，之后不再出现（`seen:ui_way_intro`，P3r3）。
- 目标条（§10.6）写的永远是「烟现在指向哪里、去干什么」，与烟和箭头一致。
- 游戏里**没有地图 App**，靠四个地标、这缕烟和香炉箭头辨认方向。

### 3.13 相册规则
- 照片渲染到 480×270 的 RT，经过同一个 composite pass，再用 `readRenderTargetPixels` 读回，生成 dataURL。两张揭示照片例外，按 960×540 存：终章全街合影 `ph_2026_group` 和凸面镜自拍（`T_mirror_self` 成功时）。
- 相册最多存 40 张。存满时自动删掉最早的一张**没有剧情标签**的照片，并提示「相册已满，已删除最早的一张」。
- 预设照片和剧情照片永不删除。剧情照片 = 标签里含有任何 `PhotoTarget.onShot.tags`（谜题、图鉴或剧情标签）的照片。
- 照片详情页显示：识别标签、游戏内时间、焦段、模式（普通/夜景）、是否闪光。可用操作：「设为对照」「删除」。

  - 设 `t0` 为她本次首次进入取景画面、且距离 ≤ 6 m 的时刻。

  - 调用 `freeze()` 时时间冻结。

  1. 和王阿婆对话，她请你拍照。

  | 出示内容 | 门禁显示 |
  |---|---|
  | 老肖像 `portrait_wall`，或没有人脸的照片 | 未检测到人脸。 |
  | 其他 NPC 的脸（`npc:*`） | 识别失败：非本小区住户。 |
  | 一张王阿婆 | 识别中……王秀英（1 号楼）。活体检测：请眨眼。（set `gate_face_ok`） |

  | 两张都闭眼 | 活体检测失败：请睁眼。 |
  | 一张睁眼 + 一张闭眼 | 活体检测通过。识别成功：王秀英。欢迎回家。 |

  - 我：……阿婆，借你的脸用一下。

### P8 `P8_chai_to_zhe` · 拆变折（第三章高潮，枢纽之一）

- **构造规则**（世界代理在构建时计算，不硬编码）：
  1. 用同一字体、同一字号，在 canvas 上分别画「拆」和「折」，逐像素相减。差出来的那块就是「那一点」。取它的质心和包围盒，作为字面上的点位 `P_glyph`。

  3. 取路面视点 `E0 = (34, 256, 1.6)`。从 `E0` 向 `P_glyph` 连线，与防尘网平面（r = 41）的交点就是 `D`（`sp_net_dot`）。点的贴片按 `|E0−D| / |E0−P_glyph|` 缩放，使它在 `E0` 看来与字上的那一点重合。
  4. 取 `V` = `vp_subway_top` 的镜头位置 (29.5, 262, 1.72)。路灯罩中心 `S = V + 0.8·(D − V)`，灯罩半径 0.28 m，灯杆立在 `S` 正下方的地面上（大约落在外侧人行道上）。遮挡判定时，灯罩用放大到半径 0.45 m 的包围球。

### 10.4 夜晚可读性要求（按评审要求，覆盖 ART §2.2 中冲突的部分）
- 天空底色抬到 `#22365a`，地面取中间调的青色。
- 受光带必须 ≥ 0.45 亮度（sRGB 值的 Rec.601 luma）。建议把月光带改为 `alb × (0.55, 0.66, 0.78) + (0.05, 0.07, 0.10)`，阴影带改为 `alb × (0.30, 0.38, 0.50) + (0.04, 0.06, 0.09)`，另加环境光下限 0.12。
- 墨线必须比它两侧的表面都暗。如果两侧平均 luma 都 < 0.18（暗色剪影），这一段改用亮色晕线 `#6d8fb0`。

## 11. 对白脚本（全部台词）

### 11.0 规则
- **节点条件写法：** `〔phase=… ｜ all=[…] ｜ none=[…] ｜ tags=[…] ｜ lens=night ｜ prio=N ｜ once〕`
  - `tags=[…]`：相册里至少有一张照片带其中任一标签。
  - `lens=night`：必须在夜景取景中按 E 才能触发。
  - 〔不在夜景〕= `lens=plain`：不在夜景取景中时才可选（`Cond.lens: 'plain'`）。
  - **没写 `prio` 的节点一律 `prio=10`。** 没写时段的节点对所有时段有效，所以带 `all=[…]` 的「之后」类节点都补了时段或场景限制（见 `chai.after`、`att.after` 等），避免和 `*.dawn` 节点同分。
- **选择节点：** 对 NPC 按 E 时，从满足条件的节点里取 `prio` 最高的一个。`once` 节点播完后记为 `seen:<nodeId>`，之后不再参与选择。
- **固定选项：** 每段对话结束后都会出现「出示照片…」和「再见」，节点可以追加自己的选项。
- **行格式：** 每行是 `说话人：台词`。「我」= 主角；「系统」= 灰色名牌，只给手机、门禁、闸机这类机器的提示音；「旁白」= 不显示名牌的叙述（NPC 的动作、§11.13 的物件文本、字条说明），`SpeakerId` 为 `narr`（P3r2）。
- **存储：** 行 key = `${nodeId}#${index}`（从 0 开始）；文本存在 `zh.ts` 的 `DLG[nodeId]` 里，每条是 `[SpeakerId, text]`。
- **变量：** 台词里的 `{name}`：`name_known` 之前替换成「？？？」，之后替换成「周远」。

## 13. 提示系统

- **渠道：** 土地的微信。每次推送前先显示「土地正在输入…」1.2 s，然后发出消息，并弹一条通知 toast。
- **当前提示对象（确定性）：** 按下面的顺序取第一个满足的：
  0. 当前目标没有 `hintFor`（夜里的 `obj_frames`）时：烟和目标条正指向的那个谜题（`SMOKE_PUZZLE[烟指向的点位]`），这样目标条、烟和土地的提示永远说同一件事（P3r3）；
  1. 最近一次有进度的、尚未完成的谜题或节拍；
  2. 当前目标 `obj_*` 对应的谜题；
  3. 夜里的枢纽阶段，按 P6 → P7 → P8 → P9 的顺序，取第一个可做且未完成的。
- **进度：** 当前提示对象的任何一个步骤 flag 被 set，就算有进度（步骤 flag 见 §10.2 和 `PuzzleDef.steps`）。每次有进度，计时器清零，已给的档位也清零。
- **起始档（P3r3）：** 已经做完的步骤不再提示。`PuzzleDef.hintFloor` / `BeatHintDef.hintFloor` 写「某步骤 flag 已 set → 最低从第几档起」：P2 `sms_full` → T3；P3 `granny_asked_photo` → T2、`gate_face_ok` → T3；P4 `idol_scanned` → T2；P5 `door403_found` / `key_rooftop` → T3；P6 `plaque_read` → T2、`trail_1987` / `lighthouse_open` → T3；P7 `subway_entered` → T2、`name_known` → T3；P9 `dot_taken` → T3；`S_darkroom` `dk_lit` → T3。低于起始档的那几档跳过：按 H 直接发起始档，自动推送的档位也整体上移（90 s 就发起始档）。
- **数据位置：** 谜题的提示在 `PUZZLES[].hints`；四个有提示的节拍（`S_studio`、`S_mirror`、`S_darkroom`、`S_group_photo`）写在 `puzzles.ts` 的 `BEAT_HINTS`（类型 `BeatHintDef`，ARCH §2.5），各自带 `availableWhen`、`steps`、`doneFlag`（分别是 `film_at_tudi`、`mirror_selfie`、`developed`、`group_photo_done`）。「当前目标对应的谜题」由 `ObjectiveDef.hintFor` 给出（`obj_p1` → P1；`obj_studio`、`obj_locker` → P2；`obj_studio_enter` → `S_studio`；`obj_temple`、`obj_gate` → P3；`obj_p4` → P4；`obj_mirror` → `S_mirror`；`obj_coop` → P5；`obj_frames` → 按第 3 条；`obj_darkroom` → `S_darkroom`；`obj_dawn` → `S_group_photo`；`obj_bus` → 无）。
- **自动推送节奏：** 没有进度满 **90 s** 推送 T1，满 **180 s** 推送 T2，满 **300 s** 推送 T3。
- **手动求助（H）：**
  - 立刻推送下一档。
  - 两档之间至少隔 **20 s**。未满 20 s 按 H 时，立刻回一条 toast「土地：别急，自己先想想，过一会儿再问老朽。」，不排队（P3r3：原来显示「土地正在输入…」却要 15–40 s 后才发，像是卡住了）；到点后再按 H 才发下一档。
  - T3 之后再按 H，重发 T3。
- 对话中、过场中、章节卡期间，计时器暂停。
- 各档提示的文本见 §9。T1 给方向，T2 给地点或动词，T3 给做法。

## 15. 结局与字幕

两个结局的流程相同（按评审的砍单：不做延时摄影，不做星球折叠）：

## 18. 内容数据格式（契约优先）

> **实现以 `docs/ARCHITECTURE.md` 为准。** 下面 §18.1 的文件布局、§18.2/§18.3 的代码块是设计时的初稿：ARCH §1.4 改了目录与归属（例如 `src/game/*` 并入 `src/core/*` 和 `src/ui/*`，`zh.ts` 拆成按归属分的 `src/data/zh/*`），ARCH §2.5–§2.7 是冻结版的 `types.ts` / `events.ts` / `contracts.ts`，ARCH §2.4 列出每一处修订。两者不一致时照 ARCH 写代码；本节的**字段含义和 id**仍然有效。

**执行顺序：** 6 个代理开工**之前**，先由一个代理写好并提交 `src/types.ts` 和 `src/events.ts`。其他人都依赖这两个文件，只能追加联合类型成员，不能改名。

import type { BeatId, ChapterId, FlagId, ItemId, ObjectiveId, PaletteKey, Phase, Photo,
  PuzzleId, ReceiverId, ShotResult, Verb, WxId, Zoom, NodeId } from './types';

export interface GameEvents {
  shutter: { burst: boolean; night: boolean; flash: boolean; zoom: Zoom };
  photoTaken: { photo: Photo; result: ShotResult };
  show: { receiver: ReceiverId; photoIds: string[] };
  puzzleSolved: { id: PuzzleId };
  verbUnlocked: { verb: Verb };
  phaseChanged: { phase: Phase; palette: PaletteKey; chapter: ChapterId };
  flagSet: { flag: FlagId };
  itemGained: { item: ItemId };
  objectiveChanged: { id: ObjectiveId };
  dialogueStart: { node: NodeId }; dialogueEnd: { node: NodeId };
  wx: { id: WxId };
  hint: { target: string; tier: 1 | 2 | 3 };
  beatStart: { id: BeatId }; beatEnd: { id: BeatId };
  uncanny: { id: string };
  enterZone: { spot: string };
}
type Handler<T> = (e: T) => void;
export class Bus {
  private m = new Map<keyof GameEvents, Set<Handler<never>>>();
  on<K extends keyof GameEvents>(k: K, fn: Handler<GameEvents[K]>): () => void {
    const s = this.m.get(k) ?? new Set(); s.add(fn as Handler<never>); this.m.set(k, s);
    return () => s.delete(fn as Handler<never>);
  }
  emit<K extends keyof GameEvents>(k: K, e: GameEvents[K]): void {
    this.m.get(k)?.forEach((fn) => (fn as Handler<GameEvents[K]>)(e));
  }
}
export const bus = new Bus();

### 20.2 容易踩的坑（补充 TECH §8）
1. 所有中文都从 `zh.ts` 取。凡是要画进 canvas 的文字（招牌、拆/折、铭牌、门牌、福字、站牌、船名、贴纸），都必须在 `document.fonts.load(font, 精确文本)` 之后再生成（TECH §5）。测试镜像要安装 `fonts-noto-cjk`，回退字体是 WenQuanYi Zen Hei。
2. 拆和折的字形都在 canvas 里用同一字体生成，之后才能做 §9 P8 的「逐像素相减求那一点」。字体换了，就必须重新计算 `sp_net_dot` 和 `sp_lamp_p8`。
3. `GHOST` 图层的物体也要走材质工厂，因为它们同样写 MRT。纸人用 alphaTest 做镂空，不能用 `transparent`。
4. 取景时 `camera.layers.enable(GHOST)` 只在夜景开启时生效；`Raycaster` 也要显式启用对应图层（TECH §3.3）。
5. 照片 RT 用 480×270，走同一个 composite；可以复用一张 MRT，尺寸在需要时切换。拍完立刻 `readRenderTargetPixels`，再用 canvas 转成 JPEG dataURL。
6. 凸面镜 RT 只在「取景中，且玩家在镜子 8 m 内」时更新，其余时间显示最后一帧，或者直接显示一块平涂的 `glassGlint`。
7. 口袋室内是独立的 Scene；切换时把星球场景的更新暂停，节省 SwiftShader 的 CPU。
8. 所有计时器（眨眼、纸妹、拆字转动、光轨循环、提示）都读模拟时间，不读 `performance.now()`，否则 `freeze()` 和 `?test` 会失效。
9. 存档里的照片 dataURL 可能接近 localStorage 的配额上限：40 张 × 约 30 KB，约 1.2 MB。写入失败时，先丢掉最早的非剧情照片再重试；再失败就只存 flag。
